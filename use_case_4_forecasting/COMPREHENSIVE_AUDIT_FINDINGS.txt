4. WEATHER FEATURES CREATED
================================================================================

DAILY FEATURES (from API):
1. temperature_2m_mean (°C) → aggregated to avg_temp
2. temperature_2m_max (°C) → aggregated to max_temp
3. precipitation_sum (mm) → aggregated to total_precip
4. sunshine_duration (seconds) → converted to hours, aggregated to sunshine_hours
5. weathercode (WMO standard) → classified to weather_condition, is_rain, is_snow, is_bad_weather

CLASSIFICATION LOGIC (Cell 7):
```python
WMO Code Ranges:
  0: Clear
  1-3: Cloudy
  45-49: Fog
  51-67: Rain
  71-77: Snow
  80-82: Rain
  85-86: Snow
  95-99: Thunderstorm
  
Derived Flags:
  is_rain: 1 if weather_condition=='Rain'
  is_snow: 1 if weather_condition=='Snow'
  is_bad_weather: 1 if condition in [Rain, Snow, Thunderstorm, Fog]
```

WEEKLY AGGREGATIONS (Cell 13):
| Feature | Method | Business Relevance |
|---------|--------|-------------------|
| avg_temp | Mean | Pool/spa heating demand |
| max_temp | Max | Peak comfort, heat wave indicator |

| sunshine_hours | Sum | Outdoor pool/spa appeal, seasonal demand |
| rain_days | Sum | Days with precipitation (mood/travel impact) |
| snow_days | Sum | Winter accessibility, travel difficulty |
| bad_weather_days | Sum | Combined adverse condition index |

ASSESSMENT: ✓ EXCELLENT
- Features are well-motivated for pool/spa/outdoor furniture retailer
- Aggregations (mean, max, sum) are appropriate for weekly grain
- WMO classification is standard and reliable
- No missing feature categories that would be critical
  * Note: Wind, humidity, UV index unavailable from free API (acceptable trade-off)

5. MISSING DATA HANDLING
================================================================================

IDENTIFICATION:
Initial merge (Cell 15) reported "Missing weather rows: 0" (MISLEADING)
Final merge (Cell 21) actually produces 591 rows with missing weather

ROOT CAUSE:
The "Liquidation" city is present in sales data (591 rows from Feb 2024 onward)
but NOT in CITY_COORDS. When merging weather by [city, week_ending], 
all Liquidation rows have no match.

IMPUTATION STRATEGY (Cell 21, lines 13-18):
```python
for col in ['avg_temp','total_precip','rain_days','snow_days','bad_weather_days','sunshine_hours']:
    if col in weekly_weather.columns:
        med = weekly_weather.groupby(['city','month'])[col].transform('median')
        weekly_weather[col] = weekly_weather[col].fillna(med)
```

IMPUTATION EFFECTIVENESS:
- ✓ Works perfectly for valid city-month combinations
- ✗ FAILS for Liquidation city: groupby returns NaN (no non-null values to aggregate)
- Result: All 591 Liquidation rows remain NaN after imputation

DEMONSTRATION:
```
Before fillna: avg_temp has 591 NaNs
After fillna:  avg_temp still has 591 NaNs
  → monthly median for Liquidation = NaN (computed from zero non-null values)
```

ALTERNATIVE IMPUTATION NOT USED:
- Province-wide median fallback (not implemented)
- Year-over-year seasonal median (not implemented)
- Forward/backward fill (not implemented)
- Linear interpolation (not implemented)

RECOMMENDATION FOR IMPROVEMENT:
```python
# Add province-wide fallback
for col in weather_cols:
    med_city = weekly_weather.groupby(['city','month'])[col].transform('median')
    if med_city.isna().any():
        med_prov = weekly_weather.groupby(['province','month'])[col].transform('median')
        med_city = med_city.fillna(med_prov)
    weekly_weather[col] = weekly_weather[col].fillna(med_city)
```
